# Codex 移动端 Web

Sparkle 启动时自动运行服务。在「应用设置 → Codex Web」只提供两个端口输入项：

| 设置           | 默认值  | 监听地址    | 用途                                      |
| -------------- | ------- | ----------- | ----------------------------------------- |
| Codex 接入端口 | `38471` | `127.0.0.1` | 接收本机 app-server 的主动 WebSocket 连接 |
| 网页访问端口   | `38472` | `0.0.0.0`   | 向局域网提供手机网页和浏览器 WebSocket    |

输入后按回车或移开焦点保存。端口被占用或保存失败时恢复原服务和设置，不自动换端口。两个端口也可设为同一个值，此时复用同一监听器，app-server 接入路径仍只接受本机连接。

同一局域网的手机使用 `http://电脑的局域网地址:38472/` 访问，无需登录；端口修改后使用相应的新地址。

在项目目录中也可以不启动 Sparkle，单独运行 `pnpm run serve:codex-web`。该命令使用默认两个端口；需要修改时可传入 `--port` 和 `--web-port`。关闭命令即可停止服务。网页必须先由 `electron-vite build` 构建到 `out/renderer`。

Release 同时提供无需源码的独立部署包：Mac ARM64 包自带 Node，通用包适合已有 Node 24+ 的环境，均内置网页、无需安装 npm 依赖。详见[独立部署说明](./codex-web-standalone.md)。源码可运行 `pnpm build:codex-web` 构建通用包；原生 Mac ARM64 环境加 `--macos-arm64` 可同时构建自带运行时的包。

## Codex 侧由用户手动配置

Sparkle 不读取、写入、检测或迁移 Codex 的配置文件，也不提供配置目录选择或自动写入按钮。请用户自行在 Codex 的 `config.toml` 顶层配置接入端口，例如：

```toml
web_server_port = 38471
```

这里填写 **Codex 接入端口**。Codex 按端口固定连接 `ws://127.0.0.1:38471/codex/app-server`；网页访问端口独立设置。

**修改 Codex 配置后，需要重启相应 app-server；使用共享后台时也需要重启后台。** Codex 按自身配置层和命令行覆盖机制读取配置。Sparkle 只接受连接，不负责判断该文件或有效配置是否已修改。

## 网页功能

- 首页直接展示会话列表，头部只保留新建入口；会话页使用单行标题，输入区平时缩成底部一行，输入时展开。编辑期间保持展开，新消息同步或手机浏览器临时失焦不收起；点击外部、切换到其他控件或发送成功后收起。草稿在收起与切换会话时保留。
- 新建会话时先浏览运行 Sparkle 的电脑并选择工作目录，再选择已连接的 Codex 服务；也可输入绝对路径跳转到目录。
- 选好目录后自动列出该项目的已有会话，可直接恢复或另建新会话。输入 `/resume` 打开恢复列表，默认仅显示当前项目，也可取消筛选查看其他项目；支持 `/resume <完整会话 ID>` 直接恢复。历史会话每页最多 20 条，点击后才恢复；会话已在已连接实例运行时，切换到所属实例。其他进程占用或恢复失败时保留原会话与输入，不强制抢占。
- 会话标题栏的文件夹按钮在新标签页打开当前项目目录，复用只读文件浏览页。
- 输入 `/delete` 后显示当前会话名称、ID、目录和永久删除确认；取消或删除失败保留原会话与输入。确认后调用原生 `thread/delete`，删除此会话及其子代理历史，并停止相关任务；成功后返回会话列表。删除通知同步到其他网页，避免继续显示已删除会话。
- 打开原实例中的会话，默认同步最近 10 条可见消息或思考入口。向上滚动到顶部附近时自动加载更早的 10 条，向下滚动到底部附近时加载较新的 10 条。当前最多渲染 20 条可见记录：向上隐藏较新的记录，向下隐藏较旧的记录；每次只发起一批请求，锁持续到渲染提交和阅读位置恢复之后，加载期间与同一手势的剩余惯性滚动均被忽略。新批次先进入有界缓冲，保持当前消息的位置，继续滚动时再逐步显示；实时消息也最多渲染 20 条，不因停留时间增加而累积。工具密集的历史可能先返回一页工具摘要。运行状态和审批独立同步，翻阅旧消息时不被实时进展拉走；点击底部图标回到最新内容。
- 正文、Markdown、行内代码和展开后的工具输出支持识别普通 URL、Windows/绝对/相对文件路径，以及 `:行:列`、`#L行`。从会话点击的链接和文件链接在新标签页打开；在目录预览中点击子目录则使用当前标签页。相对路径优先使用对应工具调用的工作目录，否则使用会话工作目录；点击后才读取文件。手机可查看只读目录、文本/代码、图片和 PDF，其他文件可下载；文本预览最多 512 KiB，过长时标注并提供完整下载。文件接口限定当前会话项目范围，并检查符号链接的真实路径。电脑 `localhost` 服务的转发留待下一阶段。
- Markdown 默认按文档格式渲染，支持标题、列表、表格、图片、代码块和清理后的内嵌 HTML；提供源码/预览切换。TypeScript、JavaScript、Python、Rust、Go、JSON、YAML、TOML、HTML/CSS 等常用源码按语言高亮，保留行列定位和原文件下载。预览模块按需加载，语法高亮在独立 Worker 中计算，不在会话页加载或执行。
- 空闲时发送新消息；运行时追加指令；停止当前回合并保留会话。
- 点击输入框展开后，点击上方的模型名称，或输入 `/model`、`/reasoning`，可修改当前会话的模型与推理强度。选项来自该实例、该会话提供商的 `model/list`；通过 `thread/settings/update` 保存，从后续任务生效。网页与终端通过 `thread/settings/updated` 同步。失败保留原设置，不通过恢复会话或发送消息来替代切换，也不读写 Codex 配置文件。
- 输入 `/` 可查看网页命令：`/goal [目标]`、`/goal pause|resume|clear`、`/goal budget <正整数|off>`、`/compact`、`/stop`、`/status` 和 `/help`。`/goal edit <目标>` 修改目标并保留当前状态，`/goal set <目标>` 设置并激活目标。命令通过原生协议执行，不作为模型提示词；暂不支持的命令保留在输入框，使用 `//` 开头可按普通文本发送一个 `/`。
- 状态区可展开查看协议已提供的模型、推理强度、目录、权限、token、目标及额度数据。上下文比例由最近一次 token 统计估算，不把累计 token 当作当前上下文占用。这些数据在同一实例重开会话时恢复。
- 向上翻阅后可一键回到底部。进展文字与思考摘要保留原有显示；它们之间的工具调用、文件修改等执行记录统一折叠，空快照和无可见内容的回合边界不拆分分组，单项操作也进入折叠区域。展开后每项细节仍默认折叠；汇总行保留失败数量与运行状态，审批卡片独立显示。
- 折叠区域不创建详情组件。展开工具组后先展示最多 20 项摘要，再按需增加；展开单项时通过 `thread/items/read` 异步读取详情，运行中的输出通过有界缓存和订阅继续更新，收起即停止详情订阅。思考详情及本轮修改同样按需读取；过长消息与输出先展示有界内容，并标注截断，完整记录保留在 Codex 中。
- 处理命令、文件修改和权限审批，回答 `item/tool/requestUserInput`。网页与终端通过 `serverRequest/resolved` 同步，重复审批不会再次提交。
- 支持 `request_user_input_async` 的消息问答：完整保留 `delivery` 和 `questions`，显示选项、自由输入及多问题表单；首项预选后仍须手动提交。回答采用 Codex 原生的 `send_user_message_question_reply` 格式，运行中追加到当前任务，空闲时开始新回合；与终端或其他网页同步已回答状态，防止重复提交。断线重连和历史窗口重新挂载时保留有界的回答草稿，失败后可重试。普通文字列表保持原有显示，不从文字推测可交互选项。
- 浏览器与 app-server 分别自动重连。重连后重新初始化、订阅和读取历史；未确认发送的消息保留在输入框，不自动重复发送。
- 手机单列列表与对话切换、固定输入区、安全区域适配，提供深浅主题；宽屏显示列表和对话双栏。网页禁用双指缩放，保留单指滚动；回到底部使用居中的图标按钮。

首页仅展示 app-server 已加载的会话；用户通过 `/resume` 或新建时的历史列表明确选择后，可恢复该实例存储中的历史会话。正在运行的会话优先加入所属已连接实例，其他进程持有写入权时显示错误，不尝试抢占。离开页面或切换会话时按浏览器引用数量取消订阅；多个浏览器查看同一会话只建立一次 Codex 订阅。

未被网页查看的离线实例会在一分钟后清理，最多保留 32 个，避免反复开关 Codex 后积累旧会话。当前打开的离线实例保留用于自动重连。刚创建、尚未生成历史的空会话若暂时不能订阅，页面提供说明和重新同步按钮。

网页新建但尚未发送消息的会话由当前 app-server 连接暂时保留；发送第一条消息后由 Codex 保存历史。app-server 断开或 Sparkle 退出前，请先发送消息以保留会话。

完整退出 CLI、自定义 `tk/s`、特殊设备验证不属于此次实现。服务使用已有会话的权限与审批策略，不改变这些策略。断线期间未持久化的流式片段不能保证恢复，已保存历史会重新同步。

`/side` 暂未接入：当前 Codex 的终端实现会组合旁支创建、权限与工具继承、上下文边界注入、持久化和终端选中状态；不能仅把 `/side` 发给模型或用普通 fork 代替完整行为。后续宜由 Codex 提供完整旁支操作的协议入口。终端 statusline 的完整选中顺序、输出速率、自定义费用等也尚未通过协议发布；逐项同步需要 Codex 提供只读快照与更新通知。Sparkle 继续不读写 Codex 的配置文件，不读取终端屏幕或自行推测这些值。

## 生命周期与模块

Sparkle 自身设置保存到独立的 `custom-codex-web.json`，不改变代理配置格式。服务运行时，自动轻量模式保留托盘进程；退出 Sparkle 或手动选择仅保留内核后，Web 服务随主进程退出。

- `src/main/custom/codex-web/`：服务、协议路由、配置、桌面 IPC 和测试。
- `src/renderer/src/custom/codex-web/`：独立移动端网页。
- `src/renderer/src/custom/codex-web-settings.tsx`：桌面设置卡片。
- `src/shared/codex-web.ts`：连接常量和两端数据结构。
- `src/renderer/codex.html`：独立构建入口，与 Electron 桌面页面分开。

上游文件仅增加后台初始化、轻量模式判断、设置卡片与构建入口。Web 网关没有 Electron IPC 转发入口；桌面 IPC 只查询服务状态和保存 Sparkle 自身的两个端口设置。

## 对接约定

app-server 主动连接 Codex 接入端口的 `/codex/app-server`，仅接受本机直接连接，读取 `x-codex-pid`、`x-codex-instance-id`、`x-codex-runtime`。实例 ID 在重连时保持不变。Sparkle 使用 `codex-backend` 初始化，开启 `experimentalApi` 与 `requiredHumanApproval`，成功后发送 `initialized`。

浏览器连接网页访问端口的同源 `/codex/browser`。网关负责将浏览器操作转换为已有协议，使用每个 app-server 独立的请求映射；审批保持原始请求 ID 类型。服务不访问 OpenAI 模型端点，也不读取 Codex 登录凭据。

历史使用 `thread/turns/list` 的 `summary` 视图和 `thread/items/list` 的小页扫描，不再读取完整回合。每次最多扫描 4 页、每页 40 项；必要时额外读取一小页，取得精确的原生边界游标，支持无重复的双向续页。原生 API 没有按内容类型过滤，Codex 到 Sparkle 的这部分条目仍可能包含工具输出，但不会转发到折叠状态的浏览器。若原生条目分页不可用，网页提示仅提供回合摘要，不退回完整历史。历史只发送一次，实时事件按 50 毫秒批量更新；审批请求立即处理。浏览器的历史缓冲最多保留三段（包括进入历史时的实时快照，合计最多 40 条可见记录），单独保留最多 20 条实时尾部；实际渲染最多 20 条，不无限缓存移除的记录。实时窗口进入历史时通过条目锚点定位当前边界，只向浏览器发送一批更早的消息。

运行 `pnpm test:codex-web` 验证连接、配置保存、历史与事件、审批、多浏览器订阅和重连；`pnpm test:custom` 包含这些测试。`electron-vite build` 会同时构建移动端入口。

Web 服务提供 `out/renderer` 中构建好的静态网页。本地开发前先构建一次；修改移动端页面后重新构建，即可在 Web 服务中刷新查看。
